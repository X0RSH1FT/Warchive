Executive Summary

The successful deployment of complex roleplaying scenarios using smaller Language Models (LLMs) presents a unique set of engineering challenges. Unlike massive models that can often compensate for structural deficiencies through sheer scale, small LLMs require highly disciplined and architecturally robust prompting techniques to maintain coherence, consistency, and character integrity over extended dialogue turns.

This report details the comprehensive methodology of Completion-Format Prompting—a structured approach that treats the entire interaction not merely as a single prompt, but as a managed, multi-turn state machine. The core findings demonstrate that achieving robust roleplay requires moving beyond simple instructions to implement a layered architecture: defining strict boundaries via System and Role Prompts; managing memory through sophisticated context preservation techniques (such as rolling summaries and state tracking); and enforcing predictable output using Few-Shot Examples within the completion format. By synthesizing these advanced prompting strategies, developers can effectively guide small LLMs to perform complex, sustained narrative tasks with unprecedented reliability.

1. Introduction: The Challenge of Small Models in Narrative AI

The field of generative AI has seen rapid advancements, yet a critical bottleneck remains when deploying sophisticated conversational agents—particularly those designed for immersive roleplay—on resource-constrained or smaller LLMs. While large models (e.g., GPT-4) can often "guess" their way to coherence using vast parameter counts, small LLMs lack this inherent redundancy and massive knowledge base. For these smaller models, every single token of input must be maximally efficient and directive.

This necessity has elevated the importance of Completion-Format Prompting. This methodology dictates that the prompt does not just ask for a response; it actively structures the expected output format, providing scaffolding that guides the model's generation process toward predictable, high-quality results [Finding 6]. In the context of roleplay—a task demanding sustained character consistency and complex narrative memory—this structured approach is not merely helpful; it is foundational to stability.

The goal of this report is to synthesize the most effective technical methodologies for building these robust systems, detailing how a multi-layered prompt architecture, coupled with advanced state management, can transform small LLMs into reliable, deeply immersive roleplaying agents.

2. Foundational Prompt Architecture: Building the Constraint Layer

To ensure that an LLM remains consistent across dozens of turns—a feat particularly challenging for smaller models—the initial prompting phase must be meticulously engineered. This requires moving beyond a single block of text and implementing a multi-component system prompt structure that defines constraints, persona, and expected output format simultaneously [Finding 2].

2.1. Role Prompting: Defining the Soul of the Character (Persona)

The first pillar is the Role Prompt, which establishes the character's identity. Merely stating "Act as a detective" is insufficient; the prompt must define the depth and manner of that role. Techniques such as 'Steering and Persona' [Finding 6] mandate defining not just the profession, but also the emotional register, specialized vocabulary, knowledge base, and relationship dynamics with the user (e.g., "You are a cynical, highly educated cybersecurity analyst who speaks in technical jargon").

Frameworks like Structured Prompt Notation (SPN) and the comprehensive CREATE framework [Finding 5] guide developers to systematically capture these details. By defining the character's expertise and tone upfront, we provide the small LLM with maximum behavioral guardrails. This level of specificity ensures that even when the model encounters ambiguity in the dialogue, its internal decision-making process defaults back to the established persona parameters, thereby maintaining deep consistency regardless of the model’s size [Finding 6].

2.2. System Prompting: Establishing Global Rules and Logic (Constraints)

The System Prompt acts as the persistent constitution for the entire session. It is the global rulebook that governs behavior irrespective of the immediate conversational flow. This component must define overarching goals, ethical boundaries, and structural constraints [Finding 6]. For advanced systems, this involves embedding complex logic using 'Workflow Control Patterns.'

These patterns allow developers to embed conditional statements (IF/ELSE) directly into the prompt's instructions. For example: IF the user attempts to break character, THEN gently redirect them by referencing a core plot point; ELSE, continue the narrative naturally. This level of explicit behavioral specification transforms the LLM from a mere text generator into an agent capable of executing predefined decision trees [Finding 3]. The system prompt thus provides the necessary scaffolding for complex interactions that would otherwise lead to unpredictable drift or failure in smaller models.

2.3. Context and Task Definition: Providing the World Lore (The Why)

A robust roleplay requires more than just rules; it needs a world. Context and Task Definition provide the why and what. This includes providing detailed background lore, established rules of physics or magic within the scenario, and the overarching goal of the interaction [Finding 10]. The C.L.E.A.R. Framework (Context, Language, Examples, Audience, Request) provides a systematic checklist to ensure no critical piece of world-building information is overlooked [Finding 5].

Crucially, this section also incorporates Background Data—any necessary reference materials that the AI must treat as absolute truth within the simulation. By providing these foundational documents and rules upfront, we minimize the cognitive load on the small LLM, allowing it to focus its limited processing power on creative dialogue rather than remembering fundamental facts about the world's history or political structure.

2.4. Completion Format Prompting: Structuring the Output (The How)

This is perhaps the most critical technical component for maximizing efficiency in smaller models. The Completion Format dictates how the model must respond, ensuring the output is predictable and usable. Instead of simply asking the LLM to "respond," the prompt provides a template—such as requiring responses to be formatted using Markdown headings, character dialogue blocks ([Character]: ...), or structured JSON objects [Finding 6].

This technique dramatically reduces the model's degrees of freedom. By enforcing structure, we guide the small LLM toward producing highly usable content that fits seamlessly into the narrative flow. Furthermore, this section must integrate Few-Shot Examples (providing 2-5 concrete input/output pairs). These examples are not merely illustrative; they are instructional, demonstrating both the desired persona and the exact required output pattern, maximizing consistency and minimizing hallucination [Finding 6].

3. Managing Multi-Turn Context and Memory Coherence: The State Machine Approach

The single greatest technical hurdle in long-form roleplay is context decay. As a conversation progresses, even small LLMs struggle to remember details from the opening turns, leading to narrative drift or factual contradictions [Finding 4]. For smaller models with limited context windows, simply feeding the entire chat history becomes inefficient and often exceeds token limits.

Therefore, advanced systems must treat memory not as a passive log, but as an actively managed resource. This requires implementing sophisticated Context Preservation Strategies.

3.1. Progressive Summarization and Rolling Context

The solution to context overload is Progressive Summarization (or "Rolling Context"). Instead of passing the entire conversation history ($H_{total}$), the system must process $H_{total}$ into a condensed, actionable summary ($\Sigma$). This mechanism actively extracts only the most critical information: key facts, emotional shifts, and unresolved plot threads [Finding 1].

The prompt structure is modified to include this dedicated memory block. The LLM reads: "Based on the following Summary of Previous Events, respond to the user's current message." By doing this, we ensure that the model retains the memory of key facts without being overwhelmed by extraneous dialogue tokens—a vital optimization for small models [Finding 1].

3.2. State Management and Structured Dialogue Frameworks

For maximum coherence, the system must implement explicit State Management. The prompt should instruct the LLM to maintain a running 'state summary' that is separate from the narrative flow. This structured state includes: 1. User Goal: What does the user want to achieve? 2. Narrative Stage: Where are we in the plot (e.g., "Investigation Phase," "Conflict Escalation")? 3. Key Facts Established: A bulleted list of non-negotiable truths (e.g., "The artifact is hidden beneath the clock tower").

This structured tracking forces the small LLM to process its own internal state before generating a response, dramatically improving factual recall and plot adherence [Finding 1].

Furthermore, advanced systems can model the dialogue using formal frameworks like Markov Decision Processes (MDPs). In this view: * State: The accumulated context/history ($\Sigma$). * Action: The model's generated response. * Reward Structure: A set of internal rules guiding the model toward responses that advance the narrative or meet predefined objectives [Finding 2].

By framing the interaction this way, we elevate the LLM from a reactive conversational partner to a proactive agent operating within defined systemic constraints [Finding 9].

3.3. Guiding Interaction Flow: Prompt Chaining and Refinement

For complex narratives that span multiple distinct phases (e.g., investigation $\rightarrow$ confrontation $\rightarrow$ resolution), simple context management is insufficient. The interaction must be broken down using Prompt Chaining. This method treats the dialogue as a series of sequential, manageable inputs. The output from Turn $N$ becomes structured feedback for the input prompt used in Turn $N+1$.

This iterative refinement process ensures continuous productive expansion and prevents the model from getting stuck or repeating itself [Finding 4]. In highly sophisticated implementations, this can evolve into Completion-Based Generation (Refinement). Instead of generating a single response, the system uses the history to generate multiple contextually tailored next-turn prompt suggestions—a form of completion that allows the user (or an external arbiter) to select the most appropriate path, thereby guiding the small LLM through complex dialogue management with maximum control [Finding 1].

4. Advanced Implementation and Robustness Techniques

To move beyond mere functionality toward true professional-grade simulation, developers must anticipate failure points and build resilience into the prompt architecture.

4.1. Handling Deviations and Edge Cases

No real-world conversation is linear. Users will inevitably introduce tangents, challenge established facts, or attempt to reset the scene. A robust system cannot simply fail when confronted with deviation. Therefore, the System Prompt must include explicit instructions on how to handle these common conversational deviations [Finding 1].

The prompt should guide the LLM: "If the user introduces a tangent unrelated to the core plot, acknowledge the tangent briefly but immediately pivot back to the established objective by referencing the current state summary." This pre-emptive instruction prevents the small LLM from becoming derailed and maintains narrative momentum even when faced with unpredictable input.

4.2. Iterative Prompt Engineering (Spec-Driven Development)

The entire process of prompt creation must be viewed as an iterative development cycle, or Spec-Driven Development [Finding 4]. This means that developers do not write a single "perfect" prompt; rather, they anticipate failure modes and build mechanisms for self-correction into the system. By defining clear constraints and utilizing comprehensive frameworks (like those detailed in the Structured Prompting Handbook), we create an architectural blueprint that guides the small LLM to maintain character and structure across all stages of the roleplay [Finding 7].

This iterative approach involves testing the prompt against edge cases—such as conflicting facts, sudden shifts in tone, or attempts at meta-commentary—and refining the System Prompt until the model's failure rate is minimized.

Completion-Format Prompting for Roleplay with Small LLMs is not a single technique but rather an entire architectural methodology. It demands a synthesis of multiple, highly disciplined components to overcome the inherent limitations of smaller models—namely, limited context window size and reduced reasoning capacity compared to their larger counterparts.
