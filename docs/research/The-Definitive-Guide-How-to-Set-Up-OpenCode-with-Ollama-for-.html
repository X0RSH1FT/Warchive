Executive Summary

Setting up OpenCode to utilize Ollama transforms your local machine into a powerful, private, and highly secure AI coding environment. This comprehensive guide details the process of integrating these two cutting-edge tools, allowing developers to leverage large language models (LLMs)—such as Gemma or Qwen—without sending proprietary code data to external cloud APIs. The core challenge lies in manually configuring OpenCode's internal settings (opencode.json) to point its API calls to Ollama’s local, OpenAI-compatible endpoint ([http://localhost:11434/v1](http://localhost:11434/v1`)). By following these steps, users gain maximum control over their data privacy while accessing state-of-the-art coding assistance.

Prerequisites: Essential Tools and Understanding

Before attempting the integration, it is crucial to understand the roles of the components and ensure your system environment is properly prepared. This setup relies on three core elements: the LLM engine (Ollama), the coding agent (OpenCode), and a robust local network connection.

1. The Role of Ollama (The Local Engine)

Ollama serves as the foundational backbone for this entire operation. It is not merely an API; it is a comprehensive, lightweight server designed to download, manage, and run various open-source LLMs locally on your hardware [Finding 1]. By running models like Gemma or Qwen through Ollama, you ensure that all computational processes—from tokenization to generation—remain entirely within the confines of your machine. This local execution is the primary mechanism guaranteeing data privacy, as no sensitive code snippets are transmitted across the public internet for processing.

2. The Role of OpenCode (The Agent)

OpenCode acts as the sophisticated interface or "agent." Its purpose is to orchestrate complex coding tasks—such as refactoring large files, generating unit tests, or completing multi-file features—and communicate those requests to an underlying LLM [Finding 3]. For this setup to work, OpenCode must be able to speak a language that the LLM server understands. This is where the critical concept of API compatibility comes into play.

3. The Importance of OpenAI Compatibility

The key technical bridge between these two tools is the OpenAI-compatible API endpoint [Finding 1, Finding 2]. While Ollama runs open models, it exposes a standardized interface that mimics the structure and function calls of the widely adopted OpenAI API (specifically at [http://localhost:11434/v1](http://localhost:11434/v1`)). This compatibility layer means that OpenCode, which is designed to interact with standard LLM APIs, can treat the local Ollama server as if it were a cloud-based service, without actually leaving your machine.

Warning: Never attempt to use an external API key or endpoint for this setup. The entire premise of this guide is achieving local processing. Using any public cloud credentials will bypass the privacy benefits and defeat the purpose of using Ollama [Finding 8].

This ensures that if your terminal session closes or your machine reboots, the LLM server automatically restarts and remains available for OpenCode.

B. Installation of OpenCode

Next, install the OpenCode CLI using its designated package manager or installation script [Finding 7]. Ensure you are installing the command-line interface version, as this is what allows manual configuration access.

Step 2: The Critical Configuration Linkage (opencode.json)

This step is arguably the most critical part of the entire setup. Since OpenCode does not have a simple GUI toggle to switch from "OpenAI Cloud" mode to "Local Ollama" mode, you must manually edit its configuration file to establish the correct communication pathway [Finding 3, Finding 7].

A. Locating and Editing the Configuration File

The system expects this configuration in a specific location, typically within your user's hidden configuration directory (e.g., ~/.config/opencode/opencode.json) [Finding 3]. Use a text editor or CLI tool to open or create this file.

B. Specifying the Local Base URL

The core of the linkage is setting the correct baseUrl. You must explicitly tell OpenCode that instead of calling OpenAI's cloud endpoints, it should direct all API requests to your local machine at port 11434 [Finding 1, Finding 2, Finding 7].

Required Base URL: [http://localhost:11434/v1](http://localhost:11434/v1`)

This specific format is essential because the /v1 suffix completes the mimicry of the OpenAI API structure, allowing OpenCode to send requests that Ollama's server knows how to interpret and process using its local models.

C. Structuring the JSON Payload

The configuration file must be a valid JSON object containing a providers block. This block defines available LLM sources. You must create an entry for "ollama" and populate it with the correct base URL, followed by a list of all model tags you pulled in Step 1 (e.g., "gemma4:latest").

Example JSON Configuration Structure:

{
  "providers": {
    "ollama": {
      "baseUrl": "[http://localhost:11434/v1",](http://localhost:11434/v1",)
      "models": [
        "gemma4:latest",
        "qwen3.5:27b"
      ]
    }
  },
  "defaultProvider": "ollama"
}

Tip: If you forget to set the baseUrl or use an incorrect port, OpenCode will attempt to connect to a non-existent endpoint (likely failing with a connection timeout) and will be unable to access your local models. Double-check that the URL is exactly [http://localhost:11434/v1.](http://localhost:11434/v1`.)

Step 3: Advanced Model Optimization for Coding Excellence

While simply pointing OpenCode to Ollama allows it to function, merely running a default model often results in suboptimal coding performance—the output might be too verbose, lack structure, or fail to maintain context across multiple files. To achieve magazine-quality code generation, optimization is necessary [Finding 10].

A. The Power of the Modelfile

Ollama allows users to create custom models using a Modelfile. This file acts like a blueprint, allowing you to fine-tune parameters and inject system instructions that guide the model's behavior specifically for coding tasks. Instead of just running the base model, you are creating an optimized version of that model.

B. Optimizing Context Length

The most crucial optimization is increasing the context window (--ctx). Standard models often operate with limited context (e.g., 4096 tokens), which means they can only "remember" a small chunk of code at a time—perhaps just one file or function.

For complex coding tasks, OpenCode needs to understand the entire module structure: how File A calls Function B in File C, and what dependencies exist. By increasing the context window significantly (e.g., setting it to 8192 tokens or higher), you allow the model to process an entire codebase segment simultaneously [Finding 10]. This dramatically improves coherence and reduces hallucination when generating code that interacts with multiple parts of a large system.

C. Refining Generation Parameters

The parameters used during generation dictate the creativity versus determinism of the output:

  • Temperature (T): Set this low (e.g., 0.1 to 0.3). A high temperature makes the model creative but unpredictable, which is disastrous for deterministic code. Low temperatures ensure that the generated code adheres strictly to conventional syntax and established patterns [Finding 10].
  • Top-P: Keep this moderate (e.g., 0.8–0.85). This controls the diversity of word choices; keeping it slightly lower than default helps maintain focus on syntactically correct, common code phrases.

By incorporating these optimizations into your Modelfile and rebuilding the model, you ensure that OpenCode is interacting with a specialized coding AI, not just a general-purpose LLM [Finding 10].

Final Usage and Verification: Testing the Connection

After completing all steps—installation, configuration linkage, and optimization—the final phase is verification.

A. Restarting OpenCode

Always restart the OpenCode CLI after making changes to opencode.json. This forces the agent to reload its provider settings and establish a fresh connection handshake with the local Ollama server [Finding 8].

B. Verification Checkpoints

  1. Model Visibility: Run an internal command within OpenCode (e.g., /models). You must see your locally pulled, optimized models listed in the expected format: <providerId>/<modelId> (e.g., ollama/gemma4:latest) [Finding 5].
  2. Functionality Test: Initiate a simple coding task (e.g., "Write a Python class that connects to a mock database"). If OpenCode successfully uses the local model and generates relevant, syntactically correct code without any connection errors or attempts to use external APIs, the setup is successful [Finding 1].

The configured Ollama model should now be selectable within OpenCode's internal model picker. You are now utilizing a private, powerful LLM agent that runs entirely on your hardware.
