Executive Summary

Starting a new software development project using OpenCode is not merely about writing code; it is an orchestrated process of establishing context, defining rules, and managing AI collaboration. This report outlines a four-phase methodology: Installation, Configuration, Initialization, and Workflow Execution. The core principle is that the quality of the final product is directly proportional to the rigor applied during the setup phase.

The initial steps require installing the OpenCode agent via CLI or IDE integration, followed by meticulous configuration of API keys and local project rules. Crucially, the process demands defining a comprehensive project context—most notably through the mandatory AGENTS.md file—which acts as the single source of truth for all collaborating AI agents. Finally, development should not begin with coding; it must start with structured planning using specialized agents (e.g., @architect, @plan) to generate detailed roadmaps before any code is written. By adhering to this rigorous, multi-step process, developers can leverage OpenCode's full potential, transforming a vague idea into a robust, architecturally sound codebase.

Quick Guide

  1. Install: Install the OpenCode agent via CLI or IDE extension (e.g., npm install -g opencode-ai).
  2. Configure: Set up API keys and create local configuration files (/.opencode.json).
  3. Contextualize: Create the mandatory AGENTS.md file in the project root to define standards.
  4. Initialize: Run the setup command (e.g., opencode github install) within the project directory.
  5. Plan: Use specialized agents (@architect, @plan) to generate a detailed roadmap and architecture before coding begins.

Prerequisites: What You Need Before Starting

Before attempting any OpenCode commands, several foundational elements must be in place. These prerequisites ensure that the environment is stable, accessible, and ready to receive complex AI instructions. Failure to address these steps will lead to unpredictable agent behavior or outright failures.

1. Development Environment Setup

You require a functional local development machine (laptop/desktop) with access to a robust terminal environment (e.g., WSL on Windows, native Linux shell). If using an Integrated Development Environment (IDE), such as VS Code, ensure that the dedicated OpenCode extension is installed and configured for optimal performance [Finding 9].

2. Version Control System (VCS) Mastery

OpenCode projects must be managed from day one within a professional VCS, specifically Git/GitHub [Finding 1]. This involves more than just initializing a repository; it requires establishing basic branching strategies (e.g., main for stable code, feature branches for development). The ability to commit, branch, and pull requests is non-negotiable, as the agent's outputs must be tracked and reviewed systematically.

3. API Credentials and Keys

The OpenCode agent itself is an orchestrator; it does not provide intelligence. It relies entirely on external Large Language Models (LLMs) for its cognitive power. Therefore, you must obtain valid API keys from your chosen LLM provider (e.g., OpenAI, Anthropic). These keys must be securely configured either as system environment variables or within the dedicated OpenCode configuration file (~/.opencode/opencode.json) [Finding 2, Finding 4].

Warning: Never hardcode API keys directly into source code or visible configuration files. Always use environment variables for maximum security and portability.

The installation phase ensures that the OpenCode agent is correctly installed and accessible across your system. The method chosen depends on whether you prefer a global CLI tool or an IDE-integrated experience.

IDE Integration (The Seamless Workflow)

If you prefer to stay within your coding environment, installing the OpenCode extension into an IDE like VS Code offers a seamless experience [Finding 9]. The benefit here is that the agent’s commands and outputs are contextually aware of the files open in the editor, which can streamline the development loop. However, even when using an IDE, ensure that any necessary environment connections (like connecting to WSL) are established first, guaranteeing optimal performance and access to local system resources [Finding 9].

Step 2: Environment Configuration (Setting the Rules of Engagement)

Once installed, the agent must be given specific instructions regarding its operational parameters. This phase is about defining how OpenCode should behave before it knows what code to write.

Configuring API Keys and Model Choice

As noted in the prerequisites, API keys are paramount [Finding 2]. Beyond simply inputting the key, you must decide which LLM model will power your project. Some advanced users may wish to use a combination of models (e.g., one for architecture planning, another for code generation). This choice is managed either globally via environment variables or locally within the project root by creating and editing /.opencode.json [Finding 8].

Defining Local Overrides

The ability to override global settings is crucial for large teams or complex projects. By placing a local configuration file, such as /.opencode.json, in the repository's root directory, you establish project-specific parameters that supersede any default settings defined by the agent’s general installation [Finding 8]. This allows a team to mandate the use of a specific model version or set of coding standards without affecting other projects on their machine.

Tip: Always verify your configuration file structure against the official OpenCode documentation. A misplaced comma or incorrect JSON format can halt all subsequent agent operations, leading to frustrating debugging sessions.

Running the Initialization Command

The Mandatory Context Files: Defining Truth

The agent cannot read your mind; it can only process the information you provide in structured text files. To ensure consistency, several context files must be created in the repository root:

A. AGENTS.md (The Project Constitution)

This file is mandatory and serves as the project's constitution [Finding 4]. It defines the overall orientation, architectural rules, coding standards, and conventions that all collaborating AI agents—whether they are generating code, reviewing it, or planning features—must adhere to. If this document is vague, the resulting code will be inconsistent; if it is detailed, the agent's output will be predictable and maintainable [Finding 4].

B. REQUIREMENTS.md (The Scope Definition)

While related to goals, this file explicitly lists functional requirements. It moves beyond general ideas ("We need a payment system") into concrete needs ("The payment system must support Stripe API v3 and handle webhooks for successful transactions"). This level of detail allows the agents to generate test cases and implementation plans with surgical precision.

C. Project-Specific Rules

For advanced control, developers should utilize dedicated rule files (e.g., .opencode/rules/*.md). These allow defining specific constraints—such as "All database interactions must use parameterized queries" or "The frontend component library must adhere to React Hooks best practices"—providing granular guardrails for the AI agents [Finding 4].

With the project fully initialized, OpenCode is ready. The method used to proceed dictates the level of structure and rigor applied to the development cycle. We compare three primary methods: general interaction, structured orchestration, and guided workflow.

A. General TUI Interaction (The Quick Start Method)

For small, contained tasks or rapid prototyping, simply running opencode in the project directory launches the Terminal User Interface (TUI). This allows for natural language conversation with the agent, making it feel like talking to a highly knowledgeable pair programmer. Use Case: Ideal for fixing small bugs, implementing minor features, or generating boilerplate code where the overall architecture is already well understood by the human team. Limitation: This method lacks inherent structure and can lead to "scope creep" if not actively managed by the developer.

For any project of significant size or complexity, adopting a structured workflow is highly recommended [Finding 4]. This approach treats development as an assembly line, where specialized AI agents perform distinct roles in sequence. Common Mistakes and Pitfalls

Even with a detailed guide, new users often fall into predictable traps. Understanding these pitfalls can save weeks of debugging time.

Mistake 1: Skipping Context Definition

The most common error is attempting to code before completing Step 3 (Initialization). If you do not create the AGENTS.md file and run the proper initialization command, OpenCode operates with an incomplete understanding of your project's boundaries. The resulting code will be generic, inconsistent, and difficult for other team members—or even future versions of yourself—to maintain [Finding 4].

Mistake 2: Treating AI Output as Final Code

Never blindly accept the first block of code generated by OpenCode. Every piece of output must be treated as a draft. The @reviewer agent is not optional; it is mandatory. Failing to review the code means accepting potential security vulnerabilities (like forgetting input sanitization) or performance anti-patterns that could cripple the application in production [Finding 4].

Mistake 3: Ignoring Version Control Best Practices

Relying on OpenCode's internal state management without proper Git commits is a catastrophic mistake. The agent operates on your repository, but it does not replace Git. Always commit frequently—after every successful @build step and before running the next specialized agent command. This ensures that if an AI process fails or introduces instability, you can revert to a known, working state [Finding 1].

To successfully start a new project using OpenCode, one must adopt a methodical, multi-stage approach that prioritizes planning over execution. The process is not simply "run the code"; it is an orchestrated series of setup and definition steps.

The definitive path involves: 1. Preparation: Ensuring all prerequisites (API keys, VCS, CLI/IDE) are met. 2. Contextualization: Running opencode github install or /init to bootstrap the agent into the project structure. 3.
